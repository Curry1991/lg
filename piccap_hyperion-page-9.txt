satdx62 03/28/2025 10:59 AM
The WS2811/Neon is not the ideal LED strip for Ambilight as it is not
designed to control individual LEDs. It controls groups of three LEDs.
If you want to control fewer than three LEDs, this is not possible with
the WS2811. This means that instead of 60LEDs/metre, only 20LEDs/metre
are available. The SK6812RGBW or the WS2812B, on the other hand, are
designed for controlling individual LEDs. For those who require precise
control of a single LED, the SK6812RGBW or the WS2812B offer a better
solution than the WS2811. There is a WS2811 for 12V and a WS2811Neon for
24V. The WS2811 for 12V expects a level of at least 5V on the data line.
Since most ESP's work with 3.3 volts, they must use a level converter
between GPIO and data from LEDs input. ESP is supplied with power from a
separate 5 volt power supply unit or via USB. The LEDs require a 12 or
24 volt power supply. The GND of the power supply units must be
connected to the GND of the ESP and the - pole of the LEDs. But since
you bought a WS2811Neon with 24 volts, I doubt that they will harmonize
with WLED. You can follow this WLED thread here and ask the author of
WLED questions:https://github.com/wled/WLED/issues/963 (edited)

satdx62 03/23/2025 1:21 PM
C4 OLED has enough resources, so don't worry. The WLED itself is a
firmware that needs to be flashed on ESP32, for example, or is flashed
by default in some Ready LED controllers. However, communication does
not take place internally on the local host/USB, but via Wi-Fi.
Therefore, a poor Wi-Fi connection can lead to a longer delay. There is
also a special HyperSerial WLED firmware for ESP controllers. There are
also ESP32 with LAN interface to which WLED can be flashed. I therefore
recommend the HyperSerial/HyperSerialPico firmware, which is controlled
via USB, instead of the WLED firmware. HyperSerial can be flashed to
certain ESP32 and HyperSerialPico to RP2040 controllers. Yes, you can
control everything with Home Assistant

footy1337 If I would run HyperHDR on a raspberry pi, would it work for
all sources including TV apps?
satdx62 03/11/2025 12:44 PM
I see no reason to install HyperHDR for the normal Ambilight on a
Raspberry Pi. The communication between PicCap and HyperHDR is internal,
so there are no network delays as everything runs on the local host. If
you want to calibrate LUT's yourself, you could do this on a Windows
HyperHDR server in the short term by redirecting the PicCap output to an
external HyperHDR for calibration. Even if you install HyperHDR
externally on a Raspberry Pi, the internal LG apps that are affected by
the DRM restrictions will not work. It is therefore advisable to feed
Netflix and the like via HDMI, as no restrictions apply here.
Nevertheless, a fixed effect/background colour can be set and activated
via prioritisation if required. For example, when using internal apps
with DRM.

The best solution is to divide the highest resolution. This has been
suggested by previous speakers who divide 3840x2160 by 10 and use
384x216. A resolution divided by 20, such as 192x108, should also work.

image. This also affects color reproduction. Unfortunately, some
device/webOS combinations only work with certain resolutions. Even with
a division by 15 (256x144) it works perfectly for me. I also wonder why
PicCap is set to 360x180 by default and not 384x216. If you calibrate
HyperHDR internally, 1280x720 is sufficient, but I recommend a
calibration on an external HyperHDR for example on Windows/Raspberry Pi
with 1920x1080 resolution. (edited)
