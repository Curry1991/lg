    weak_alias is a feature in the GNU C library (glibc) that allows the definition of a weak symbol that can be overridden by a strong symbol at link time. In other words, it allows multiple symbols to refer to the same underlying function or variable, but with different levels of strength.
    The primary reason for using weak_alias in glibc is to provide a level of backwards compatibility for functions that have been renamed or moved to different libraries over time. When a library function is renamed or moved, it can cause issues for programs that were compiled against the old function name or location. By using weak_alias, the old function name or location can still be used as an alias for the new function, without breaking existing programs.
    Another reason for using weak_alias is to allow the creation of library functions with different names that share the same implementation. This can be useful in cases where multiple functions perform the same underlying operation, but have different names to indicate different levels of abstraction or behavior.

    netbsd_patch_builtin (enum built_in_function fncode)
    {
      tree fn = builtin_decl_explicit (fncode);
      tree sym;
      char *newname;
      if (!fn)
        return;
      sym = DECL_ASSEMBLER_NAME (fn);
      newname = ACONCAT (("__c99_", IDENTIFIER_POINTER (sym), NULL));
      set_user_assembler_name (fn, newname);
      fn = builtin_decl_implicit (fncode);
      if (fn)

    }
