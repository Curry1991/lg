image in real-time, then neural is overshot here because LUt doesn't
"know" the picture, it's a simple mapping without the context. You can
train the network using more images but the same result can be achieved

take one raw pixel captured from webOS (and let say it's a lucky one,
because we have it captured earlier so no interpolation) but still you
have dozen candidates for the real one. And averaging cause colors to
lose their intensity. (edited)

red for the input again. The colors were bleak (averaging) and without
tonal transitions (averaging + interpolation because of missing 95%) on
the test boards.

[] yolofant has anyone looked into how a LUT could be calculated from 2

awawa_dev 08/23/2022 8:32 PM
If you don't know the transformation then you need to create much more
images, where boxes cover 256^3 colors  I made exactly such approach
for USB grabbers earlier and it was a disaster: only around 5% of the
color space were covered, but mysteriously some of the missing 95%
colors could appear later in the video stream...probably as a result of
dithering, most results overlapped so you don't know the exactly revers
transformation value for them. The final solution which work much better
assumes that we know the transformation but we don't know some of its
parameters. But it was HDR and USB grabbers, who knows how it works for
LG. You can use the calibrator from HyperHDR. So far I've got only one
report with a score of 15k which means the quality for HDR is much worse
than standard USB grabber result. (edited)
