hellobox. 12/18/2022 3:06 AM
webOS 7/22 has a different version of libcrypt than the ssh server
included with the homebrew channel app (dropbear) is looking for:
libcrypt.so.2 vs. libcrypt.so.1. please test the attached files (patched
to use either version of libcrypt): replace dropbear/sftp-server in
/media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/bin,
but keep backups. original workaround: 1. put a copy of libcrypt.so.1
from older webos (libcrypt.so.1.1.0 attached) somewhere writable: e.g.,
/media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/lib
(which you'll have to create) 2. make a symlink to it named
libcrypt.so.1. e.g.:
    ln -s libcrypt.so.1.1.0 /media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/lib/libcrypt.so.1
    3. modify the homebrew startup script by adding `LD_LIBRARY_PATH="/media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/lib${LD_LIBRARY_PATH:+:${LD_LIBRARY_PATH}}"` to the beginning of the command that starts `dropbear` (if you don't care about keeping the existing value of `LD_LIBRARY_PATH` you can just use `LD_LIBRARY_PATH='/media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/lib'`). example:
    sh
    sed -e'/dropbear -R/s@^\s*@&LD_LIBRARY_PATH="/media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/lib${LD_LIBRARY_PATH:+:${LD_LIBRARY_PATH}}" @' -i.bak /var/lib/webosbrew/startup.sh(original backed up as `startup.sh.bak`)
    if you'd rather not mess with the startup script, instead of step 3 you can disable sshd in homebrew channel settings and create a separate startup script:sh
    cat > /var/lib/webosbrew/init.d/10-dropbear << "EOF"
    #!/bin/sh
    LD_LIBRARY_PATH="/media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/lib${LD_LIBRARY_PATH:+:${LD_LIBRARY_PATH}}" /media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/bin/dropbear -R
    EOF
    chmod +x /var/lib/webosbrew/init.d/10-dropbear
