According to awawa-dev, there is a function UYVY To NV12 in libyuv. But
it depends on whether this yuv422 is planar or not (UYVY), but the
number of planes can be checked in webOS. In UYVY there are no planes,
it starts UYVY 4 bytes for every 2 pixels. In the version without planes
(if any) it is similar to NV12, first Y bytes, then separate U and V
planes so as not to confuse them.

satdx62 01/25/2025 9:16 PM
Many users have problems getting PicCap/hyperion webos to work under
webOS 3.4 or 3.5. Either the device starts in failsafe mode and the
autostarts are not executed, or PicCap freezes on certain SoCs. Since
SSH works on them, this means that the failsafe mode is not triggered.
But since PicCap freezes, you have to start PicCap (hyperion-webos)
without GUI. So you have to create the config.json yourself and move it
to /media/developer/apps/usr/palm/services/org.webosbrew.piccap.service/
and restart it. Then you should be able to see if the data is arriving
at Hyperion or HyperHDR. config.json
    {"priority":150,"backend":"auto","address":"127.0.0.1","port":19400,"width":192,"height":96,"fps":25,"vsync":false,"autostart":true,"nogui":true,"novideo":false,"uibackend":"auto"}
    With the following commands in Terminal, you can now start PicCap and check whether everything is OK:
    cd /media/developer/apps/usr/palm/services/org.webosbrew.piccap.service
    ./hyperion-webos --verbose
    Autostart can be achieved by linking  /media/developer/apps/usr/palm/services/org.webosbrew.piccap.service/piccapautostart to  /var/lib/webosbrew/init.d/, but I don't know if the old webOS supports it.
    Just check with :
    luna-send -n 1 -f luna://org.webosbrew.piccap.service/status '{}'
Sie könen die config.json aus Anhang dafür nutzen. (edited)
