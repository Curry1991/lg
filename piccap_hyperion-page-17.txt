Hi, for understanding: PicCap grabs/captures the image content and sends
the information to Hyperion or HyperHDR. This in turn processes the
information from PicCap and is passed on to the LED controller which can
be either an ESP32 or a Raspberry PI Pico. Both the PicCap and the
Hyperion can be set up on TVs. The Hyperion UI can be accessed from the
PC/mobile browser under the IP address of the TV on
PORT:8090.(92.168.178.x:8090.) From there the LED controller and the
layout will be configured. This can also do without controller and LEDs
in the under LED controller “file” selects and a fake layout created.
Only then you could see under LED visualization if that works. (edited)

Both Hyperion and HyperHDR serve the same purpose, which is to convert
PicCap screen capture data into usable control signals for WLED/LEDs
strips. Why install Hyperion or HyperHDR server externally on a
Raspberry, when you can install on your LG. Besides, the data is
transferred directly to the local host and not via detours like LAN or
WI-FI. This way there is no unnecessary delay/lag. Each of the two
Hyperion variants has its existence justification. One likes this, the
other that. Just test both. Of course, only one of the two may be
active. The settings of HyperHDR/Hyperion can be exported and imported
again if needed.

satdx62 08/17/2023 12:28 PM
The problem is not the ESP32 itself, but the drivers for your TVs. For
the webOS on LG, the correct drivers must be installed to enable
communication between HyperHDR installed on the TV and HyperSerial
connected via USB. Either compile yourself or use a driver compiled by
@hellobox from this forum that is appropriate for your SoC architecture.
See the links. So I was able to successfully run “Hyperserial” from
Awawa on ESP32. Check which USB chip is on your ESP32 board. 1) Upload
the driver file to your TV, run insmod yourdriverfile.ko in Terminal. 2)
Connect ESP, check if you have a new /dev/ttyAMA0 (or something similar)
now. 3) In the HyperHDR web interface, select the “ada protocol” and
configure it with the new device /dev/tty*.
