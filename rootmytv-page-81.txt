hellobox. 10/07/2022 1:56 AM
webos 22 has a newer/different version of libcrypt than previous webos
versions: libcrypt.so.2 rather than libcrypt.so.1. the ssh server
included with the homebrew channel app, dropbear, is looking for
libcrypt.so.1. workaround: 1. put a copy of libcrypt.so.1 from an
earlier version of webos
(https://discord.com/channels/407937994037919756/822443030761046017/1019731178145714286)
somewhere writable: for example,
/media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/lib
2. make a symlink to it named libcrypt.so.1. example:
    ln -s libcrypt.so.1.1.0 /media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/lib/libcrypt.so.1
    3. modify the homebrew startup script by adding `LD_LIBRARY_PATH="/media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/lib${LD_LIBRARY_PATH:+:${LD_LIBRARY_PATH}}"` to the beginning of the command that starts `dropbear` (the shell variable stuff is to be compatible with existing values of `LD_LIBRARY_PATH`; if you don't care you can just use `LD_LIBRARY_PATH='/media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/lib'`). example:
    sh
    sed -e'/dropbear -R/s@^\s*@&LD_LIBRARY_PATH="/media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/lib${LD_LIBRARY_PATH:+:${LD_LIBRARY_PATH}}" @' -i.bak /var/lib/webosbrew/startup.sh(this will create a backup of the original `startup.sh` as `startup.sh.bak`)
    if you'd rather not risk messing with the startup script, you can do this instead of step 3:
    3a. disable sshd in homebrew channel settings
    3b. create a separate startup script to run `dropbear`:sh
    cat > /var/lib/webosbrew/init.d/10-dropbear << "EOF"
    #!/bin/sh
    LD_LIBRARY_PATH="/media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/lib${LD_LIBRARY_PATH:+:${LD_LIBRARY_PATH}}" /media/developer/apps/usr/palm/services/org.webosbrew.hbchannel.service/bin/dropbear -R
    EOF
    chmod +x /var/lib/webosbrew/init.d/10-dropbear
