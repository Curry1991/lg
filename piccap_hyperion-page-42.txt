What I am outlining is not WLED specific, it applies to all Hyperion
instance components and device types
03/09/2022 4:19 PM
As Hyperion now sits on the TV, it could react on triggers by the OS.
For example, if CoreElect goes into suspend it triggers a SIGUSR1 which
disabled Hyperion’s instances. Disabling the instance will either switch
of WLED or restore its state before Streaming. When CoreElec wakes up,
it triggers SIGUSR2 wich puts WLED in streaming mode. Same could be
achieved via API commands. (edited)
[.pclin]
.pclin 03/09/2022 2:39 PM
Since you can also use WELD for purposes other than 'only' with
Hyperion, terminating/switching off WLED is not always desirable. If you
also use WLED as lighting or for sound reactive or LEDfx, that always
causes other problems. In the HyperionControl plugin for dreamOS I have
installed various options (turn off, color, effect, preset, sync on/off)
for how the behavior should be. Another possibility is via WLED directly
by setting a preset that e.g. switches the LEDs black. (edited)
