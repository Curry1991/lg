[analyticeth]
analyticeth 01/28/2026 4:14 AM
Hey @taco5780 great that someone else is looking at this too! I haven’t
had time to investigate this recently due to family events but I should
have more time this week. The WebOS CONFIG_HZ is 250 per the open source
kernel info I grabbed off of LG’s site. WebOS has 64 bit kernel space
and 32 bit user spaces as well. I'd recommend grabbing the Fire TV GPL
source code if you haven't already  Regarding kallsyms/hardcoded
addresses: I looked into this approach but I'm not sure its viable for
WebOS. The problem is we only have heap address leaks (task_struct,
sigqueue addresses), not kernel text/data leaks. Since heap and kernel
text are randomized independently (due to the CONFIG_RANDOMIZE_BASE=y in
the kernel), knowing init_cred's offset from _stext via kallsyms doesn't
help without a way to leak a kernel text address at runtime first. My
current approach is instead of trying to point task->cred at init_cred,
I'm using an arbitrary write to overwrite task->cred with a pointer to a
fake cred struct that I control on the heap. The challenge now is
getting the exact offset from task->pending.list to task->cred in the
task_struct, whcih is currently crashing because the offset is wrong. My
next steps are to try out other offsets incrementally, but its a manual
process with a lot of waiting time for each run to hit. cc: @ciaranc
