Hi, With HyperHDR's comprehensive JSON API (Advanced --> JSON API), you
can control virtually all parameters in Home Assistant. This works
either via a static HTTP link or by sending a JSON payload as a POST
request to “IP:PORT/json-rpc” to an RPC HyperHDR service. Multiple
commands can be executed with a single link. Since you can also
configure a wide variety of settings on the LG via Luna requests, many
automations are possible. However, you can also easily create two
brightness profiles using the LG Input Hook, which you can then
conveniently access at any time using two remapped buttons on your LG
remote control. I’ve remapped one profile for daytime and one for
nighttime on the remote. LEDs Luminance value 1 Browser (HTTP):
    http://192.168.x.x:8090/json-rpc?request=%7B%22command%22:%22adjustment%22,%22adjustment%22:%7B%22classic_config%22:false,%22luminanceGain%22:1%7D%7D
    SSH/Input Hook:
    curl http://192.168.x.x:8090/json-rpc?request=%7B%22command%22:%22adjustment%22,%22adjustment%22:%7B%22classic_config%22:false,%22luminanceGain%22:1%7D%7D
    LEDs Luminance value 2
    Browser (HTTP):
    http://192.168.x.x:8090/json-rpc?request=%7B%22command%22:%22adjustment%22,%22adjustment%22:%7B%22classic_config%22:false,%22luminanceGain%22:2%7D%7D
    SSH/Input Hook:
    curl http://192.168.x.x:8090/json-rpc?request=%7B%22command%22:%22adjustment%22,%22adjustment%22:%7B%22classic_config%22:false,%22luminanceGain%22:2%7D%7D
You must enter the correct IP address for your TV in the command line.
You can find an Input Hook that works with newer TVs here:

Hyperk was developed as an alternative to existing WLEDs. These are
usually flashed onto ESP WiFi boards or supplied with compatible LED
controllers. Hyperk can also be used via a LAN cable on the ESP32 ETH-01
or compatible devices with a LAN interface. Since our webOS devices are
a special case and both HyperHDR and the grabber (PicCap) run directly
on our TVs, controlling the LED controllers via USB is a great
advantage. Most HyperHDR/Hyperion.NG users do not have this advantage
and have to find a way to host or connect the software and the grabber.
A direct, wired connection to the LED controller is therefore not always
possible. HyperSerial or HyperSerialPico are the better alternatives for
us. The RP2040 Pico with built-in level shifter is better than the ESP32
S2 Mini, as the level converter is already integrated, which makes
cabling much easier and the hardware resources more powerful. If you
already have the ESP32-S2, you will need to connect a level shifter in
between. In one of my tutorials, you will find various wiring diagrams,

satdx62 02/13/2026 7:31 PM
PicCap (hyperion-webos) via Terminal/SSH: Open the PicCap app and press
'Stop' to end capturing. Then open Terminal/SSH and enter the following,
replacing the IP address with that of your TV:
    /media/developer/apps/usr/palm/services/org.webosbrew.piccap.service/hyperion-webos --verbose -s -b libdile_vt -f 0 -x 192 -y 108 -a 192.168.x.x
You can stop 'hyperion-webos' with CTRL + C. Copy the terminal output
into an editor and post it here. HyperHDR-Logs: Open HyperHDR in your
PC's browser. Then enter your TV's IP address:8090. (192.168.x.x:8090)
Next, under 'General Settings' > 'Logging', set the log level to
'Debug'. Then navigate to the bottom of the menu to 'Logs'. Paste the
content into a text editor using 'Copy to Clipboard' and save it as a
.txt file.

[] ak_3d Rasbery pi is pricey, can i use esp32 instead ?
satdx62 02/07/2026 10:19 AM
With an external Ambilight solution, only signals from external sources
such as a Fire TV Stick or a Roku TV can be processed. The YTAF must run
on the external device and not on the LG device. A Raspberry Pi serves
as a host for HyperHDR or Hyperion NG and as a port for the USB grabber.
In addition, a splitter is required to tap the HDMI signal for the
grabber and forward it to the TV. An ESP serves only as an LED
controller. If you had a mini PC available, you could save on almost
everything and only need the ESP, the LEDs, and the appropriate power
supply. As an alternative to the LEDs, you can use an inexpensive LED
kit such as the Skydimo or a similar product from the Chinese market.

when watching television. Ambilight is, so to speak, surround sound in
color for televisions. It works very well with PicCap/HyperHDR when

WebOS is a special case for Ambilight and differs completely from
external solutions with USB grabbers and the embedded HyperHDR solution
on a device other than WebOS.

Hi, According to the developers of HyperHDR, the old
'flat_lut_lin_tables.3d' files with a size of 50 MB from
/media/developer/apps/usr/palm/services/org.webosbrew.hyperhdr.loader.service/hyperhdr/,
will no longer be supported in the new versions of HyperHDR. Instead,
only the standard size of 150 MB, as used in 'lut_lin_tables.3d', or the
compressed form as 'lut_lin_tables.3d.zst' will be supported. The
self-calibrated LUTs have the standard size of 150 MB and are stored as
'lut_lin_tables.3d' in /home/root/.hyperhdr/. However, you can also load
a default uncompressed LUT if necessary. The 'Disable Hyperhdr SDR/HDR
switch' is located under PicCap Advanced Setting. (edited)

satdx62 01/16/2026 4:45 PM
Hello, To take full advantage of NV12, it must be activated in PicCap.
Then install the compressed or uncompressed LUTs using the HyperHDR
Loader. There are three different LUTs for common content types such as
SDR, HDR, and DV. Compressed LUTs are equivalent in quality to
uncompressed LUTs, but take about one second to decompress and load when
changing content. However, at around 22 MB, they only take up a fraction
of the flash memory compared to the uncompressed LUT tables, which take
up a total of around 450 MB. I personally use the compressed LUTs. If
you select the By default option, only a universal LUT will be installed
and the NV12 option in PicCap must be deactivated.

iganesh. 01/11/2026 1:09 PM
It depends. If your TV is rooted, I would suggest running Hyperion
directly on the TV, because then you do not need to keep another
computer or Raspberry Pi running. If the TV is not rooted, then you will
obviously need to run Hyperion from a different device. That said, it is
not strictly necessary to run Hyperion on the TV itself. You can also
run it on another machine. Benefit-wise, running it on the TV is mainly
for convenience, since you do not need an extra device like a Raspberry
Pi or another computer running all the time. There is no major
performance benefit compared to running it on a separate machine. I hope
this answers your question. (edited)
