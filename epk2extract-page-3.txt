    Key requirements for XIP
    The storage must be randomly addressable at the byte level (NOR flash works; NAND flash does not, since NAND is block/page addressed and not memory-mapped).
    The filesystem and kernel must cooperate to avoid copying XIP pages into the page cache.
    The architecture must support executing code from the flash's memory-mapped address range.
02/20/2026 12:49 PM
    cramfs compresses data, but XIP requires uncompressed data to execute directly. The combination works like this:
    cramfs with XIP support stores read-only, executable data (code segments) uncompressed, so they can be XIP-mapped.
    Data that doesn't need XIP (non-executable data, things that need to be writable) can still be compressed normally.
02/20/2026 12:48 PM
    XIP — Execute in Place
    This is where XIP comes in. XIP solves the RAM cost problem by allowing code to be executed directly from the storage medium (typically NOR flash or ROM) without copying it into RAM first.
    Normally, when you run a program, the kernel copies its pages from storage into RAM and executes from there. With XIP:
    The storage medium (e.g., NOR flash) is memory-mapped — it appears directly in the CPU's physical address space, just like RAM.
    The MMU maps pages from flash directly into the process's virtual address space.
    The CPU fetches instructions straight from flash over the memory bus — no copy needed.
    This saves potentially megabytes of RAM, which is precious on embedded devices.

     */
    void decryptImage(void *srcaddr, size_t len, void *dstaddr) {
        unsigned int remaining = len;
        unsigned int decrypted = 0;
        while (remaining >= AES_BLOCK_SIZE) {
            AES_decrypt(srcaddr, dstaddr, aesKey);
            srcaddr += AES_BLOCK_SIZE;
            dstaddr += AES_BLOCK_SIZE;
            remaining -= AES_BLOCK_SIZE;
            decrypted++;
        }
        if (remaining != 0) {
            decrypted = decrypted * AES_BLOCK_SIZE;
            memcpy(dstaddr, srcaddr, remaining);
        }
    }
