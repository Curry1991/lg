https://gist.github.com/Informatic/1983f2e501444cf1cbd182e50820d6c1#luna-service-bus-debugging
this may be somewhat useful. tl;dr on how luna works → system exposes
services, which expose methods, which can be called and accept some
arguments (as JSON objects) and return one or many JSON responses.
com.webos.service.config seems like a service responsible for
"hardware-level" / per-model configuration (since webOS firmware images
are the same across similar TVs in a specific year, eg. all 2019 OLEDs
use the same firmware, but some may have some differences in features -
that's where config service comes in). It has a bunch of methods which
can be discovered by running ls-monitor -i com.webos.service.config.
Parts of high-level explanation of how it works is available in webOS
OSE (which is forked off LG's webOS TV, some things may be the same,
some may have minor changes, and some things are just completely
missing) →
https://www.webosose.org/docs/reference/ls2-api/com-webos-service-config/
There's also /etc/configd directory which has a bunch of scripts that
actually set these config values based on model number and other stuff.
(keep in mind this directory itself is read-only and it'd be best to
just override some options after startup using luna calls instead of
replacing these files)
