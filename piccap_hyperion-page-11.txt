satdx62 01/23/2025 10:37 PM
Install ‘LG Input Hook’ via Homebrew Channel. After installation, start
the app and a page will be displayed on the screen with a URL and its
password, which you can call up on the PC. With ‘Add keybind’ you can
assign a new function to a button on your remote control. Example 1: The
brightness in HyperHDR should be reduced from 100 to 70 on the red
button on your remote control. Under Key binds, ID:398 and Action:
Execute. ‘Under Command’, enter the following command for 70 %:
    curl http://127.0.0.1:8090/json-rpc?request=%7B%22command%22:%22adjustment%22,%22adjustment%22:%7B%22classic_config%22:false,%22brightness%22:70%7D%7D
    Example 2:
    On the green button of your remote control, the brightness in HyperHDR should be increased from 70 to 100, then assign a new function with ‘Add keybind’.
    Under Key binds, ID:399 and Action: Execute.
    ‘Under Command’, enter the following command for 100 %:
    curl http://127.0.0.1:8090/json-rpc?request=%7B%22command%22:%22adjustment%22,%22adjustment%22:%7B%22classic_config%22:false,%22brightness%22:100%7D%7D
After each key assignment, do not forget to save the settings with ‘Save
Changes’. Important! If you want to undo the settings, then assign the
original ID. See list in appendix. This method can also be used to
execute other commands with the remote control, provided that there are
keys with functions that are not absolutely necessary. Have fun testing.
I would be pleased to receive your feedback. (edited)

Hi, In the near future, we will be able to work with compressed LUT's
that are only about 18 MB instead of 150 MB with normal compression.
HyperHDR should automatically recognise that the uncompressed file does
not exist and try to find and load a compressed file with the extension
.xz. This has the advantage that devices with less flash memory can also
benefit from the various NV12/YUV LUT tables. For some users, this fails
due to the lack of memory. This is already working, but awawa-dev wants
to work on the new decompression algorithm (ZSTD compression for all

Good news for Hyperion.NG users!  NV12 implementation by @Lord-Grey
for Hyperion.NG users. See
https://github.com/hyperion-project/hyperion.ng/commit/6e3357ea2d43a122070d6ff6bc689d6c1f487ff3
Since the color conversion is implemented internally, unlike HyperHDR,
Hyperion.NG does not require “HDR to SDR tone mapping” and for this
reason no LUT's table is needed. There is also a “SizeDecismation” for
standard RGB/RGBA and NV12 input, in case one or the other runs out of
LG resources and the CPU load becomes too high. For this, as for
HyperHDR, you had to install and activate the new hyperion-webos (PicCap
with) with NV12 support backend. See:
https://github.com/satgit62/Ultimate-HyperHDR-Ambilight-fine-tuning-experience-for-LG-webOS-with-new-LUT-calibration-#1replace-backends-in-hyperion-webos-piccap
I have already compiled an NV12 Flatbuffer /“flutbuffer” Branch from
Hyperion.NG and adapted it for LG webOS. Download for testing on LG:
https://github.com/satgit62/hyperion.ng-webos-loader/actions/runs/12099896912/artifacts/2257143522
Otherwise, nv12 branch “flutbuffer” from @Lord-Grey is merged in the
master. The tests are positive and promising. Thanks at this point to
@Lord-Grey for the implementation. Direct color calibration is made
easier if Kodi is installed on the TV. This is done here interactively
by switching on the remote control function of Kodi and thus both
programs communicate with each other and exchange data. I had to change
the Hyperion.NG loader so that the screen saver no longer terminates the
Hyperion daemon. This means that the connection to the Hyperion server
is maintained even when the screensaver is activated so that the
calibration can be completed. Please note that you must set the EXPERTE
setting level in order to access certain functions, and The Kodi
calibration server will only be recognized by Hyperion if you start Kodi
before the calibration. And have enabled the remote control function.
