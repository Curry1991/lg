[awawa_dev]
awawa_dev 06/18/2022 3:20 PM
The final image can be over-saturated when HDR LUT table is applied for
SDR image. Standard HyperHDR LUT table probably used in
hyperhdr-webos-loader is for captured images using BT2020 color space
(completely different than standard (s)RGB/bt709 typical for SDR) and
HDR PQ gamma (causing SDR content much too bright). And some few other
tweask to make it look better for the typical USB grabber but probably
unnecessary for pure webOS/DirectX etc capturing. I don't have an access
to rooted LG anymore so I can't test it now, but from my previous
analyses BT2020/PQ is the most popular case when capturing on webos. The
second one produces very dark images (DV or depended on input? don't
know), they are broken for some reason and can't be properly fixed: only
adjust brigntness/saturation to make it look better. Probably this
procedure can provide proper LUT table for typical webos scenariuo but
it's only speculation: didn't test it and don't know what will happen
https://ibb.co/515RB4L. My previous manual attempt to fix webos HDR
stream can be found in the HyperHDR archive
https://github.com/awawa-dev/HyperHDR/blob/6a74ded1267414978721627e1679c0a2f8c4da22/resources/lut/for_webos_hdr_flat_lut_lin_tables.tar.xz

The wled issue with Hyperion.NG is fixed for some time now, the warning
in the pdf tutorial is outdated. The reason why it was problematic: in
some cases the network was not fully up when Hyperion daemon tried to
connect to the WLED device - this made it hang. As UDP is a stateless
protocol, it didn't care for WLED to be up, it just sent data and did
not require any acknowledgement. In short: WLED is the protocol to go
for, either on Hyperion.NG or HyperHDR
